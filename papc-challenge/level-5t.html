Theory, on paperList programs, and induction

A list program is a few equations

Write \(t :: l\) for the list with first row \(t\), then the list \(l\). Every list is either \([\,]\) or \(t :: l\), and a program on lists gives one equation for each.

Definition 5T.1 (Selection and projection on lists)

\[\begin{aligned} \mathit{select}\ p\ [\,] &= [\,] \\ \mathit{select}\ p\ (t :: l) &= t :: \mathit{select}\ p\ l && \text{if } p(t) = \true \\ \mathit{select}\ p\ (t :: l) &= \mathit{select}\ p\ l && \text{if } p(t) = \false \\ \mathit{project}\ f\ [\,] &= [\,] \\ \mathit{project}\ f\ (t :: l) &= f(t) :: \mathit{project}\ f\ l \end{aligned}\]

Here \(p\) is a condition with values in \(\B = \{\true, \false\}\), as a program needs. These lists represent \(\sel{p}(R)\) and \(f[R]\) (Level 6 proves it). The equations are also how the programs run: each step rewrites with one of them.

Induction proves a fact about every list

Principle (Induction on lists)

To prove \(P(l)\) for every list \(l\): prove \(P([\,])\); and prove \(P(t :: l)\) for every row \(t\) and list \(l\), assuming \(P(l)\).

It is the induction of the Natural Number Game: \([\,]\) plays \(0\), and \(t :: l\) plays \(n + 1\). Why is it sound? Every list is built from \([\,]\) by adding rows in front, one at a time, and each step carries \(P\) from the shorter list to the longer one.

Fact 5T.2

\(\mathit{length}(\mathit{project}\ f\ l) = \mathit{length}(l)\), for every list \(l\).

Proof. By induction on \(l\). For \([\,]\), both sides are \(0\). For \(t :: l\): the length of \(\mathit{project}\ f\ (t :: l) = f(t) :: \mathit{project}\ f\ l\) is \(1 + \mathit{length}(\mathit{project}\ f\ l)\), which is \(1 + \mathit{length}(l)\) by the assumption \(P(l)\), the induction hypothesis. ∎

A proof by induction is a recursive function

The proof of Fact 5T.2 follows the program \(\mathit{project}\) case by case: the case \([\,]\) uses its first equation, and the case \(t :: l\) its second, plus the induction hypothesis for the shorter list \(l\). That is a recursive call: a proof by induction is a recursive function that returns proofs. So, to prove a fact about a program, follow the program's own cases.

Law 1 holds for lists, too

Fact 5T.3

\(\mathit{project}\ f\ (\mathit{project}\ g\ l) = \mathit{project}\ (f \circ g)\ l\).

Fact 5T.4 (Law 1, for lists)

\(\mathit{select}\ p\ (\mathit{select}\ q\ l) = \mathit{select}\ (p \wedge q)\ l\), as lists: the same rows, in the same order.

Proof. By induction on \(l\). For \([\,]\), both sides are \([\,]\). For \(t :: l\), take the cases of \(q(t)\) and \(p(t)\):

  • if \(q(t) = \false\), both sides drop \(t\), and the induction hypothesis finishes;
  • if \(q(t) = \true\), both sides keep \(t\) exactly when \(p(t) = \true\), and then the induction hypothesis finishes again.

∎

Fact 5T.4 is stronger than law 1: it says the lists are equal, not only the tables they represent. Not every law is that strong: Question 5T.D finds one that holds for tables but not for lists.

Questions

Question 5T.A Projections compose

Prove Fact 5T.3 on paper.

Answer

By induction on \(l\). For \([\,]\), both sides are \([\,]\). For \(t :: l\): the left side is \(\mathit{project}\ f\ (g(t) :: \mathit{project}\ g\ l) = f(g(t)) :: \mathit{project}\ f\ (\mathit{project}\ g\ l)\), which by the induction hypothesis is \((f \circ g)(t) :: \mathit{project}\ (f \circ g)\ l\): the right side.

Question 5T.B Selection never makes a list longer

Prove \(\mathit{length}(\mathit{select}\ p\ l) \leq \mathit{length}(l)\).

Answer

By induction on \(l\). For \([\,]\): \(0 \leq 0\). For \(t :: l\), with the induction hypothesis \(\mathit{length}(\mathit{select}\ p\ l) \leq \mathit{length}(l)\): if \(p(t) = \true\), both sides grow by 1; if \(p(t) = \false\), the left side stays and the right side grows by 1.

Question 5T.C Law 2 for lists

Is \(\mathit{select}\ p\ (\mathit{select}\ q\ l) = \mathit{select}\ q\ (\mathit{select}\ p\ l)\), as lists?

Answer

Yes. By Fact 5T.4, the two sides are \(\mathit{select}\ (p \wedge q)\ l\) and \(\mathit{select}\ (q \wedge p)\ l\), and \(p(t) \wedge q(t) = q(t) \wedge p(t)\) for every row \(t\).

Question 5T.D A law that lists break

Compute \(\mathit{product}\ [a, b]\ [x, y]\), and the list you get from \(\mathit{product}\ [x, y]\ [a, b]\) by swapping each pair. Are they equal as lists? Do they represent the same table?

Answer

\([(a, x), (a, y), (b, x), (b, y)]\) and \([(a, x), (b, x), (a, y), (b, y)]\): the same pairs, in a different order. Not equal as lists, but they represent the same table. So "the product is commutative, up to swapping" holds for tables, not for lists. Level 7 calls this equality as bags.

The programs, in Lean

Leanlists.lean
def select {α : Type} (p : α → Bool) : List α → List α
  | [] => []
  | row :: rest => if p row then row :: select p rest else select p rest

def project {α β : Type} (f : α → β) : List α → List β
  | [] => []
  | row :: rest => f row :: project f rest

def product {α β : Type} : List α → List β → List (α × β)
  | [], _ => []
  | a :: rest, s => project (fun b => (a, b)) s ++ product rest s

Definition 5T.1, and the product of Level 3F: copy them, or use yours if you did the programs track (TPIL 8.1 Pattern Matching). They go outside namespace Sets.

Fact 5T.2 in Lean: your first proof by induction

Leaninduction.lean
theorem project_length {α β : Type} (f : α → β) (t : List α) :
    (project f t).length = t.length := by
  induction t with
  | nil => rfl
  | cons row rest ih => simp [project, ih]
  • The same proof as on paper: one case for nil, the empty list, and one for cons, a first row and the rest.
  • In the cons case, ih is the induction hypothesis: (project f rest).length = rest.length.
  • simp [project, ih] rewrites with the equations of project, with ih, and with the lemmas Lean knows about length, until the goal is closed (TPIL 5.7 Using the Simplifier).

Exercise 5T.1 In Lean Replay it with rw

Replace simp [project, ih] with rw steps, and watch the goal change in the Infoview after each one (TPIL 5.6 Rewriting).

Hint

rw [project] unfolds one step of the program. Then List.length_cons rewrites the length of x :: l to l.length + 1, and ih finishes.

Exercise 5T.3 In Lean Law 1 for lists

Prove Fact 5T.4. Induction on l. In the cons case, take the cases of the conditions, as on paper: cases hq : q row and cases hp : p row. Then simp [select, hp, hq, ih] finishes each case.

Hint
